# Source-bound editorial review protocol

This optional procedure strengthens editorial reasoning without changing [the Constitution](../00_Project/Constitution.md), canon promotion, preservation permissions, or prose authorization. Read [AGENTS.md](../AGENTS.md) and [the workflow](WORKFLOW.md) first. Inspection of an inbox or manuscript requires authorization; a file path is not consent.

## 1. Establish an exact evidence boundary

Record repository, branch, inspected commit, review question, book, scene, viewpoint, and author-approved scope. Enumerate only actually inspected files with paths, record IDs, passages or message anchors, source class, coverage (whole file or excerpt), and authority. Distinguish approved canon from decisions, current manuscript continuity, development, preserved artifacts, external research, and inference. The latest modified file does not automatically supersede an approved decision.

Use [the Writing Context Brief](../09_Tools/Templates/Writing_Context_Brief.md) for major writing tasks. An evidence register is not authorization to inspect otherwise restricted material. Unavailable sources limit conclusions; cite them as gaps.

## 2. Make three bounded, evidence-driven review passes

- **Continuity:** compare shared objective events, chronology, ages, mechanics, established dialogue, dependencies, and the applicable approved facts.
- **Character:** compare motivation, knowledge at the exact moment, mistaken beliefs, emotional development, and credible behavioral changes.
- **Reader experience:** compare narrative voice, pacing, clarity, per-book revelation ceilings, and standalone payoff. Respect deliberately withheld facts.

A single reviewer may perform labelled passes; claim independent agents participated only when they actually did. Do not let a simulated debate's apparent winner become story authority.

## 3. Classify rather than overwrite

Use CONFIRMED CONFLICT, POSSIBLE ISSUE, INTENTIONAL MYSTERY, or EDITORIAL OPTION. Every confirmed conflict must identify the challenged passage and controlling evidence, with exact citations, confidence and impact. Keep review severity separate from certainty. State alternative interpretations and where reviewers disagree. Do not manufacture errors or reinterpret a character's false belief as a narrator-level contradiction without evidence.

The author decides creative changes. No review output becomes canon, an approved scene, or a manuscript revision automatically. Use [the Review Report](../09_Tools/Templates/Review_Report.md).

## 4. Track consequences and review again

For an approved change, list documented dependencies and possible further effects separately: characters, events, scenes, plot threads, books, narrative revelations and editions. Mark each as checked, needs revision, unaffected with explanation, or unknown. Re-review only the affected criteria after a bounded authorized correction; do not loop indefinitely or make undocumented changes.

The [series and continuity guide](SERIES_AND_CONTINUITY.md) remains authoritative for relationships and event order. This protocol adds structured evidence and editorial reporting, not a second canon index.

## 5. Optional source-packet check

The optional [review packet template](../09_Tools/Templates/Review_Packet.json) and [validator](../scripts/validate_review_packet.py) compare an explicitly named UTF-8 source, SHA-256, line ranges and optional exact excerpts. They do not interpret claims or attest author approval. Read [tool limitations](TOOLS.md#optional-source-bound-review-packets) before running.

Source status, actual consent, evidence strength, and correctness of interpretations remain editorial decisions. Public framework fixtures must be synthetic; private manuscripts and conversations must never be copied into public framework tests.
